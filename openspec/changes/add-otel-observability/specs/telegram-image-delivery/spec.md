## MODIFIED Requirements

### Requirement: Generated media follows retention and privacy controls
Pending generated-image bytes SHALL be included in application backup and restore so acknowledged queueing remains recoverable. Sent or cancelled generated bytes SHALL be erased when the configured retention cutoff is applied. Image bytes and private image content MUST NOT appear in ordinary logs, health output, delivery errors, or text fields used for diagnostics. When tracing is explicitly configured, bounded and redacted textual prompt or caption content MAY appear in the trace backend; image bytes and authentication values MUST NOT.

#### Scenario: Database is backed up with a pending image
- **WHEN** an application backup is created while a generated image is pending and then restored into a fresh runtime
- **THEN** the restored image intent contains the bytes and metadata required to resume delivery

#### Scenario: Retention runs after image delivery
- **WHEN** a sent or cancelled generated-image intent is older than the configured retention cutoff
- **THEN** its binary image content and private error detail are removed while minimal delivery metadata may remain

#### Scenario: Operator inspects diagnostics after a photo failure
- **WHEN** image delivery health or ordinary logs report a Telegram upload failure
- **THEN** those diagnostics contain no generated bytes, prompt content, caption content, or authentication value

#### Scenario: Operator inspects a configured trace
- **WHEN** tracing is enabled for a turn involving image generation or a photo caption
- **THEN** the trace may contain bounded, redacted text content but contains no image bytes or authentication value
